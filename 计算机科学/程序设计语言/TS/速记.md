# Promise
## Promise 三种状态（状态不可逆，一旦改变不会再变）
1. `pending`：等待中，初始状态
2. `fulfilled(resolved)`：成功，拥有结果值
3. `rejected`：失败，拥有错误原因
> 状态只能：pending → fulfilled，或者 pending → rejected；**状态一旦落定，不能修改**。
## 创建 Promise
```js
const p = new Promise((resolve, reject) => {
  // 异步操作，比如定时器、网络请求
  setTimeout(()=>{
    resolve("成功的数据") // 把状态改为fulfilled
    // reject(new Error("失败")) // 改为rejected
  },1000)
})
```
- `resolve(val)`：将 Promise 置为成功，val 作为结果
- `reject(err)`：将 Promise 置为失败，err 作为错误
## 实例方法
1. `.then(onFulfilled, onRejected)`
    接收成功回调，返回**新 Promise**，支持链式调用
```js
p.then(data=>{
  console.log(data)
  return 123
}).then(v=>console.log(v))
```
2. `.catch(onRejected)`
    捕获链上的错误，等价于 `.then(null, err=>{})`
3. `.finally()`
    无论成功失败都会执行，不接收结果，不改变链的值
> 重点：`.then`永远返回新 Promise，所以可以链式，不是修改原来的 Promise。
## Promise 静态方法
1. `Promise.resolve(value)`：直接返回一个已成功的 Promise
2. `Promise.reject(err)`：直接返回一个已失败的 Promise
3. `Promise.all([p1,p2,p3])`
全部成功才成功；任意一个 reject 立刻失败（快速失败）
4. `Promise.race([p1,p2])`：**第一个落定（不管成功失败）就结束**
5. `Promise.allSettled([p1,p2])`：全部完成，不管成功失败，收集每一个结果
6. `Promise.any([p1,p2])`：第一个成功就成功；全部失败才失败
## async 函数和 Promise 的关系
`async function` 的返回值一定被包装为 Promise：
```js
async function f(){
  return 1
}
//等价于
function f(){
  return Promise.resolve(1)
}
```

`await p`就是等待 p 这个 Promisesettle；成功拿值，失败抛出异常给`try/catch`捕获。

> async/await 只是 Promise 的语法糖，底层全部是 Promise。

# 3、Promise 背后原理、宏任务、微任务（事件循环 Event Loop）

> JS 是**单线程**，同一时间只能做一件事；异步不是开多线程，靠事件循环，任务队列实现。

## 两个队列：宏任务队列、微任务队列

### 宏任务（macrotask）

代表大块的异步任务，每一次事件循环**只取一个宏任务执行**。

来源：

- `setTimeout`、`setInterval`
- script 整体脚本代码（初始执行）
- I/O、UI 渲染、setImmediate

### 微任务（microtask）

优先级高于宏任务。**当当前同步代码执行栈清空之后，把微任务队列里面所有任务一次性全部跑完，才去取下一个宏任务**。

来源：

- Promise `.then/.catch/.finally`回调 ✨最重要
- `await`后面的代码本质就是放进微任务队列
- `MutationObserver`

### 事件循环执行完整流程（核心，必背）

1. **调用栈清空**（当前同步代码全部执行完）
2. **把微任务队列所有任务全部拿出来，依次执行，直到微任务队列为空**
    
    > ⚠️执行微任务过程中，如果又产生新微任务，新微任务继续在本轮全部执行完，不会留给下一轮
    
3. 微任务全部清空之后，才从**宏任务队列取出 1 个宏任务**放到调用栈执行
4. 执行完这个宏任务后，回到步骤 2 循环

> 口诀：**同步代码 → 清空全部微任务 → 执行一个宏任务，循环往复**
