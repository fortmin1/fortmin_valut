# 检修目标
迁移自建PostgreSQL数据库到阿里云PolarDB PostgreSQL。
# 产生事故
1. 页面数据缺失
2. 数据泄露
# 原因分析
1. 事前检修计划写的一般，浮于表面，没有详细思考每一步的意义，涉及到的内容。
2. 迁移数据库是高危操作：
	1. 缺少专业DBA指导
	2. 准备时间不足，至少提前一周准备，同时应该对数据库迁移专门撰写一份分析和操作报告。
	3. 缺少专业DBA，且公司的DBA对阿里云的PolarDB也不熟悉，同时现场指挥和操作人员没有专门调研学习，缺乏敬畏心和专业知识。
	4. 阿里云工作人员无法提供专业知识，DTS工具没有提前申请，依然是上面提到的，至少提前一周开始准备，这次提前两天才开始申请DTS，DTS无法使用的情况下，直接导致后续的大量问题。DTS无法使用的情况下，阿里云工作人员建议使用navicate进行数据迁移，这是极其不专业的建议！
	5. 现场操作人员没有仔细思考问题现象对应的实际原因，一方面缺少专业知识，一方面没有多加思考，盲目下判断，后续补救由于方向错误，造成了二次事故和大量时间的浪费。
	6. 我具备一定的专业知识，但是对于现场操作没有决策权，也没有主动参与事故分析。也没有坚持自己的意见，同时缺乏经验，听取了阿里云工作人员的建议使用navicate进行数据迁移，浪费了大量时间，同时引入了风险。
   3. 数据泄露源于三方的私搭乱建，这部分我没有参与，但是我应该思考下怎么通过管理防止这种情况再度发生。

2. 做事不要浮于表面，一定要深入思考，内容最重要。
