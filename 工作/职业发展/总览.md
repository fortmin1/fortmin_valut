一个完整的软件研发组织其实可以分成四条线：

```
                公司战略
                    │
        ┌───────────┼───────────┐
        │           │           │
    产品体系      技术体系     项目体系
        │           │           │
 Product Manager  Tech Lead   Project Manager
 Product Owner    Architect   Scrum Master
                  Engineering Manager
                  Developer
                  QA
                  SRE
```
# 技术体系
## Developer（研发工程师）
job:
- 编码
- Bug修复
- Code Review
- 单元测试
- 文档
require:
	技术能力
	工程能力
## Senior Developer（高级工程师）
job:
不仅能写代码，还能独立负责模块。
他开始承担：
- 技术方案
- Code Review
- 指导新人
## Tech Lead（技术负责人）
job:
对一个团队的技术结果负责。
Tech Lead负责：
```
技术方案

代码规范

任务拆分

技术难题

Review

上线质量
```
## Architect（架构师）
架构师最大的职责：

> **保证整个系统未来三五年仍然能支撑业务发展。**

job:
例如：
一个电商。
架构师设计：
```
Gateway

↓

User

↓

Goods

↓

Order

↓

Trade

↓

Pay

↓

Inventory
```
再决定：
```
Redis

Kafka

MySQL

ES

OSS

Seata
```
如何组合。
更多关注:
```
CAP

一致性

高可用

分库分表

缓存

DDD

微服务

云原生
```
输出：
各种：
```
架构图

时序图

部署图

技术选型

规范
```
## Engineering Manager（研发经理）
**真正的管理岗。**

他最大的职责：

> **管理人，而不是管理代码。**

## Director（技术总监）
开始：

管理多个团队。

例如：

下面：

```
支付组

订单组

搜索组

AI组

推荐组
```

都有自己的：

Tech Lead。

Director负责：

整个研发部门。
## CTO
最高技术负责人。

关注：

整个公司的技术战略。

例如：

```
是否云原生？

是否AI？

是否全球部署？

是否重构？
```

更多的是：

商业决策。

## SRE（Site Reliability Engineer）

Google提出的岗位。

主要负责：

> **系统稳定运行。**

以前：

叫：

运维。

现在：

更偏：

软件工程。
