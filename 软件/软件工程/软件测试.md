## 一、按是否查看源代码（最基础分类）

1. **白盒测试（结构测试）**
    
    看代码内部逻辑、分支、路径，检查代码逻辑、覆盖率。

> 技术：语句覆盖、分支覆盖、路径覆盖；单元测试、代码走查。

2. **黑盒测试（功能测试）**
    
    不关心内部代码，只看输入输出，验证软件功能是否符合需求。

> 技术：等价类、边界值、场景法、错误推测；集成、系统测试大多是黑盒。

3. **灰盒测试**
    
    介于黑白盒之间，既看部分接口 / 数据库，又做业务功能验证，多用于接口测试。

## 二、按测试阶段划分

1. **单元测试**：测最小代码单元（函数、类），开发人员做，白盒为主。
2. **集成测试**：模块之间交互、接口，模块拼接后测接口调用、数据传递。
3. **系统测试**：完整整个软件，在真实环境，完整业务流程，黑盒为主。
4. **验收测试**：客户 / 产品确认是否可以上线。
    
    - α 测试：开发环境，内部模拟用户
    - β 测试：真实用户现场使用（公测）
    

## 三、按测试目的 / 专项测试

### 1. 功能测试

验证功能是否满足需求文档，最基础测试。

### 2. 性能测试

- **压力测试**：不断加压，找系统崩溃临界点
- **负载测试**：模拟正常预期并发，看系统表现
- **并发测试**：多用户同时操作，测并发冲突
- **稳定性测试**：长时间运行，看内存泄漏、资源占用
- **容量测试**：大数据量下系统表现

### 3. 兼容性测试

不同操作系统、浏览器、版本、分辨率、设备，验证是否正常。

### 4. 安全测试

漏洞、权限、注入攻击、越权访问、密码安全、接口防篡改。

### 5. UI 界面测试

页面布局、样式、文字、弹窗、按钮显示，交互体验。

### 6. 易用性测试（用户体验）

操作是否简单、符合用户习惯。

### 7. 接口测试

对 API 接口入参出参、异常、业务逻辑校验，现在互联网项目高频。

### 8. 回归测试

修改 bug 后，重新测原有功能，防止改出新 bug。

### 9. 冒烟测试

版本刚提测，快速跑核心流程，判断版本能不能进入正式测试。

### 10. 探索性测试

不按用例，测试人员凭经验自由探索找 bug。

### 11. 配置测试

不同服务器配置、数据库版本、环境参数软件运行情况。

### 12. 安装卸载测试

安装、升级、降级、卸载是否正常。

## 四、其他常见概念

- **手工测试**：人手动操作
- **自动化测试**：脚本执行，UI 自动化、接口自动化
- **随机测试**：随意操作，随机输入找异常
